# Упражнения

*Цель: намеренно нарушить каждую гарантию из предыдущих глав и заранее предсказать, к какой именно
ошибке это приведёт.*

Каждое упражнение состоит в одном небольшом изменении, нарушающем одну из гарантий, описанных в
предыдущих главах. Прежде всего запишите своё предсказание: какой инструмент сообщит об ошибке,
какой именно и почему. Затем выполните команду и сравните результат с предсказанием. Предсказание
ошибки учит большему, чем чтение о ней, а неверное предсказание — самый полезный из возможных
результатов, поскольку оно точно указывает, какую идею следует перечитать. Все приведённые ниже
ответы проверены на этом коде, а тексты ошибок даны дословно, в том виде, в каком их выводят
компилятор или программа запуска тестов.

**Рабочей копией** (англ. worktree) называется дополнительный рабочий каталог того же репозитория
Git. Упражнения следует выполнять в ней, чтобы не затронуть основной рабочий каталог. Только для
упражнений 7 и 9 требуется macOS, причём в них используется фальшивый клиент; ни одно упражнение не
устанавливает и не выбирает метод ввода.

```sh
git worktree add --detach ../keyrill-lesson HEAD
cd ../keyrill-lesson
git checkout .                     # after each exercise
cd - && git worktree remove ../keyrill-lesson   # when finished
```

Каждое упражнение начинается с чистого рабочего каталога. После каждого упражнения следует выполнить
`git checkout .` и убедиться, что `git status --short` ничего не выводит; исключение составляет лишь
упражнение 4, которое выполняется поверх изменения из упражнения 3. По окончании рабочую копию нужно
удалить последней командой из приведённого выше блока.

| № | Изменение | Запуск | Вопрос |
| -- | -- | -- | -- |
| 1 | Добавьте `self.serial += 1;` первой строкой `transition` в `crates/keyrill-core/src/session.rs` | `cargo check -p keyrill-core` | Можно ли заставить писать метод, принимающий `&self`? |
| 2 | Добавьте вариант `Teleport` в `enum Action` в `session.rs` | `cargo check -p keyrill-ffi` | Какой крейт сообщит об ошибке и где? |
| 3 | Допишите `fn sneak() { unsafe {} }` в конец `crates/keyrill-core/src/mapping.rs` | `cargo check -p keyrill-core` | Считается ли пустой блок `unsafe`? |
| 4 | Поставьте `#[allow(unsafe_code)]` в строке над `sneak` | `cargo check -p keyrill-core` | Может ли одна функция выйти из-под `forbid`? |
| 5 | В `NativeEvent` в `crates/keyrill-ffi/src/lib.rs` замените `units: [u16; 8]` на `[u16; 9]` | `cargo check -p keyrill-ffi` | Что обнаружит изменение ABI? |
| 6 | Удалите `#[repr(C)]` над `NativePlan` | `cargo check -p keyrill-ffi` | Обнаружится ли изменение, если размер может остаться прежним? |
| 7 | В `include/keyrill.h` удалите три строки, открывающие `extern "C" {`, и закрывающую его `}` | `native/macos/build.sh check` | Заголовочный файл по-прежнему компилируется как C; что увидит адаптер? |
| 8 | В `acknowledge` замените `outcome == Outcome::Verified` на `outcome != Outcome::Unknown` | `cargo test -p keyrill-core` | Что пойдёт не так, если отказ продвигает состояние? |
| 9 | В `apply:` в `native/macos/src/KRSession.mm` удалите проверку поколения сразу после записи (строки 507 и 508) | `native/macos/build.sh check` | Заметна ли одна пропущенная перепроверка? |

## Ответы

Читать ответы следует только после того, как записаны предсказания для всех упражнений.

1. `` error[E0594]: cannot assign to `self.serial`, which is behind a `&` reference ``. Это
   невозможно без замены сигнатуры на `&mut self`, а тогда пришлось бы изменить и весь вызывающий
   код, который опирается на то, что переход является чистой функцией. См.
   [владение и заимствование](rust.ru.md#%D0%B2%D0%BB%D0%B0%D0%B4%D0%B5%D0%BD%D0%B8%D0%B5-%D0%B8-%D0%B7%D0%B0%D0%B8%D0%BC%D1%81%D1%82%D0%B2%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D0%B5).
1. `` error[E0004]: non-exhaustive patterns: `keyrill_core::session::Action::Teleport` not covered ``
   в крейте `keyrill-ffi`, в том `match`, который превращает действие в его номер для C; само ядро
   по-прежнему компилируется. Новый случай не может незаметно пройти через ABI. См.
   [`match` ведёт счёт](rust.ru.md#match-%D0%B2%D0%B5%D0%B4%D1%91%D1%82-%D1%81%D1%87%D1%91%D1%82).
1. `` error: usage of an `unsafe` block ``. Линт реагирует на сам блок, а не на его содержимое;
   кроме того, компилятор предупреждает, что блок не нужен.
1. `error[E0453]: allow(unsafe_code) incompatible with previous forbid`, а вслед за ней та же
   ошибка, что и в упражнении 3. В этом и состоит различие между `forbid` и `deny`: уровень `deny`
   можно было бы ослабить для отдельного элемента, а `forbid` — нельзя.
1. `error[E0080]` с `assertion failed: size_of::<NativeEvent>() == 32`. Проверка выполняется
   компилятором, ещё до компоновки. См.
   [шаг 1](boundary.ru.md#%D1%88%D0%B0%D0%B3-1-%D0%B4%D0%BE%D0%B3%D0%BE%D0%B2%D0%BE%D1%80%D0%B8%D1%82%D1%8C%D1%81%D1%8F-%D0%BE-%D1%80%D0%B0%D1%81%D0%BF%D0%BE%D0%BB%D0%BE%D0%B6%D0%B5%D0%BD%D0%B8%D0%B8-%D0%B2-%D0%BF%D0%B0%D0%BC%D1%8F%D1%82%D0%B8).
1. `error[E0080]` с `assertion failed: std::mem::offset_of!(NativePlan, expected) == 24`. Без
   `repr(C)` компилятор переставляет поля; одной проверки размера для обнаружения этого было бы
   недостаточно, поэтому закреплено и смещение.
1. Адаптер компилируется, но не компонуется: выводится `Undefined symbols for architecture arm64:`,
   а за этим следуют имена вроде `"kr_engine_new(unsigned int, kr_engine**)"`. Это сигнатуры C++,
   раскодированные компоновщиком, тогда как библиотека Rust экспортирует `_kr_engine_new` без типов
   параметров. См.
   [связывание C](objective-cpp.ru.md#%D1%81%D0%B2%D1%8F%D0%B7%D1%8B%D0%B2%D0%B0%D0%BD%D0%B8%D0%B5-c).
1. Не проходят два теста: `unknown_refused_and_reset_expire_pending_and_receipt` и
   `history_is_acknowledged_bounded_and_expires_with_authority`. При таком изменении отклонённый
   план устанавливает своё предложенное состояние, хотя ничего не было записано, и Rust считает
   существующей разметку, которой в документе нет.
1. `session_tests: 1 failure(s)` в случае `lifecycle_interruption_status`, том самом тесте, что
   показан в главе
   [Реентерабельность и тесты](reentrancy-and-tests.ru.md#%D0%B2%D1%80%D0%B0%D0%B6%D0%B4%D0%B5%D0%B1%D0%BD%D1%8B%D0%B9-%D1%84%D0%B0%D0%BB%D1%8C%D1%88%D0%B8%D0%B2%D1%8B%D0%B9-%D0%BA%D0%BB%D0%B8%D0%B5%D0%BD%D1%82).
   Этот тест повторно входит в сеанс изнутри записи, а затем требует, чтобы адаптер больше не
   обращался к клиенту. Без проверки адаптер продолжает читать разметку у клиента, над которым у
   него больше нет полномочий.

## Порядок чтения исходников

| Что читать | Почему |
| -- | -- |
| `crates/keyrill-core/src/mapping.rs` | 125 строк идиоматичного кода на Rust с тестами. Начинать следует отсюда. |
| `crates/keyrill-core/src/lib.rs` | Обработка целого слова в одном примере документации, который выполняет `cargo test --doc`. |
| `crates/keyrill-core/src/session.rs` | Конечный автомат со схемами в начале модуля. |
| `include/keyrill.h` | Контракт с точки зрения C. Вступительный комментарий — лучшее краткое описание проекта в репозитории. |
| `crates/keyrill-ffi/src/lib.rs` | `with_engine`, затем `kr_plan_event` и `kr_commit`. |
| `native/macos/src/KRKeys.mm` | 47 строк на Objective-C++ — самое простое введение в язык. |
| `native/macos/src/KRSession.h`, `KRSession.mm` | Сначала сценарий в заголовочном файле, затем методы `runEvent:` и `apply:`. |
| `native/macos/tests/session_tests.mm` | Класс `FakeClient`, затем один тест на повторный вход. |
