# Глоссарий

В документации используются сокращения, языковые термины и ряд терминов, имеющих в этом проекте
точный смысл. Сокращение снабжено ссылкой на источник, где оно определено, а языковой термин —
ссылкой на раздел учебника, где он вводится. Для терминов проекта внешнего источника нет, поэтому
они определены здесь, со ссылкой на страницу, где каждый из них разобран подробно.

## Сокращения

| Сокращение | Значение |
| -- | -- |
| ABI | [Двоичный интерфейс приложения](https://en.wikipedia.org/wiki/Application_binary_interface) (application binary interface): имена, соглашение о вызовах и расположение структур на машинном уровне; в Keyrill это `include/keyrill.h` |
| ADR | [Запись архитектурного решения](https://adr.github.io/) (architecture decision record); записи Keyrill лежат в [`docs/adr`](adr/README.ru.md) |
| API | [Программный интерфейс приложения](https://en.wikipedia.org/wiki/API) (application programming interface) |
| ARC | [Автоматический подсчёт ссылок](https://clang.llvm.org/docs/AutomaticReferenceCounting.html) (Automatic Reference Counting): вызовы retain и release, вставляемые компилятором Objective-C |
| ASan | [AddressSanitizer](https://clang.llvm.org/docs/AddressSanitizer.html), детектор ошибок памяти clang |
| BOM | [Метка порядка байтов](https://www.unicode.org/faq/utf_bom.html#BOM) (byte order mark), U+FEFF в начале текстового файла |
| CC BY-SA | [Creative Commons Attribution-ShareAlike 4.0](https://creativecommons.org/licenses/by-sa/4.0/), лицензия данных о словах в модели |
| CI | [Непрерывная интеграция](https://en.wikipedia.org/wiki/Continuous_integration) (continuous integration); здесь — процессы GitHub Actions в `.github/workflows` |
| COM | [Component Object Model](https://learn.microsoft.com/en-us/windows/win32/com/component-object-model--com--portal), объектная система Windows, на которой построен TSF |
| DLL | [Динамически подключаемая библиотека](https://learn.microsoft.com/en-us/troubleshoot/windows-client/setup-upgrade-and-drivers/dynamic-link-library) (dynamic-link library), разделяемая библиотека Windows |
| EWT | [English Web Treebank](https://universaldependencies.org/treebanks/en_ewt/index.html), один из корпусов для оценки |
| FFI | [Интерфейс внешних функций](https://doc.rust-lang.org/nomicon/ffi.html) (foreign function interface): вызовы между Rust и другим языком; здесь — крейт `keyrill-ffi` |
| GCD | [Grand Central Dispatch](https://developer.apple.com/documentation/dispatch), библиотека очередей Apple |
| GTK | [GTK](https://www.gtk.org/), набор инструментов для настольных приложений Linux |
| HRESULT | [Код состояния Windows](https://learn.microsoft.com/en-us/windows/win32/com/structure-of-com-error-codes), возвращаемый методами COM |
| IMK | [InputMethodKit](https://developer.apple.com/documentation/inputmethodkit), фреймворк macOS для методов ввода |
| IPC | [Межпроцессное взаимодействие](https://en.wikipedia.org/wiki/Inter-process_communication) (inter-process communication); каждый вызов клиента IMK — такое взаимодействие |
| MSVC | [Набор инструментов C и C++ от Microsoft](https://learn.microsoft.com/en-us/cpp/) и целевая платформа Rust для Windows, которая его использует |
| RAII | [Resource acquisition is initialization](https://en.cppreference.com/w/cpp/language/raii) («получение ресурса есть инициализация»): объект C++, деструктор которого отменяет то, что сделал конструктор |
| SHA-256 | [Криптографическая хеш-функция](https://en.wikipedia.org/wiki/SHA-2); закрепляет исходные данные модели и корпуса ради согласованности, а не подлинности |
| TIS | Text Input Sources, интерфейс Carbon, который перечисляет и выбирает раскладки клавиатуры и методы ввода; см. раздел «Термины» ниже |
| TSF | [Text Services Framework](https://learn.microsoft.com/en-us/windows/win32/tsf/text-services-framework), аналог IMK в Windows |
| TUI | [Текстовый интерфейс пользователя](https://en.wikipedia.org/wiki/Text-based_user_interface) (text-based user interface), например программа, работающая в терминале |
| UBSan | [UndefinedBehaviorSanitizer](https://clang.llvm.org/docs/UndefinedBehaviorSanitizer.html), детектор неопределённого поведения clang |
| UD | [Universal Dependencies](https://universaldependencies.org/), проект трибанков, из которого взяты корпуса для оценки |
| UTF-8, UTF-16 | [UTF-8](https://en.wikipedia.org/wiki/UTF-8) и [UTF-16](https://en.wikipedia.org/wiki/UTF-16), кодировки Unicode; каждая длина в ABI считается в единицах кода UTF-16 |
| X11 | [X Window System](https://en.wikipedia.org/wiki/X_Window_System), старый графический протокол Linux |

## Термины

**Адаптер (adapter).** Платформенная часть программы, которая отвечает за нативные объекты и за
правку текста; в macOS это код на Objective-C++ в каталоге `native/macos`. Адаптер обращается к
движку через C ABI; движок к адаптеру не обращается никогда. См. [адаптер для macOS](macos.ru.md).

**Вывод (inference).** Решение движка на границе слова о том, набрано ли законченное слово в
неверной раскладке. Вывод опирается на замороженную модель, словари пользователя и недавний контекст
и оставляет слово без изменений во всех сомнительных случаях. См. раздел
[«Движок»](engine.ru.md#%D0%B2%D1%8B%D0%B2%D0%BE%D0%B4).

**Выученные слова (learned words).** Слова, которым пользователь обучил проверку орфографии
операционной системы. Они защищают и запрещают слова наравне со словарями Vim, однако автоматическое
исправление их готовности не дожидается.

**Граница (boundary).** Контекст, в котором буква может начать слово: курсор стоит в начале
документа или после пробельного символа, причём это установлено чтением у клиента. Любой другой
контекст, в том числе префикс, который не удалось прочитать, считается *недопустимым* (ineligible),
и буква передаётся приложению без изменений.

**Доказательство контролируемых нативных тестов (controlled-native evidence).** Результат нативных
тестов, в которых настоящий адаптер и настоящий движок Rust работают с фальшивым клиентом,
действующим по сценарию. Такой результат показывает, как ведёт себя адаптер в данном сценарии, но
ничего не говорит о настоящем приложении: о нём может свидетельствовать только физический тест. См.
[тестирование](testing.ru.md).

**Квитанция (receipt).** Текст слова до его первого преобразования в Keyrill. Квитанция хранится,
пока то же слово принадлежит Keyrill, чтобы сочетание Control-Option-Z или клавиша Escape могли
восстановить исходный текст. Правка или завершение слова делают квитанцию недействительной.

**Локальные полномочия (local authority).** Сведения адаптера о последней проверенной им разметке:
клиент, начальное смещение и точный текст. Без этих сведений запись невозможна; перед каждой записью
адаптер их сбрасывает и восстанавливает только после того, как проверки записи пройдены, а для
обновления разметки это означает совпадение обратного чтения с ожидаемым.

**Неизвестный исход (unknown outcome).** Подтверждение, которое адаптер выдаёт для предпринятой
записи, если её результат проверить не удалось. Такое подтверждение делает сеанс недействительным и
прекращает исправление; ничего не исправляется и не повторяется.

**Обратное чтение (readback).** Чтение композиции у клиента после записи, строго по записанному
диапазону. Это единственное доказательство результата записи, которое принимает адаптер; успешный
код возврата API таким доказательством не является. Без обратного чтения проверенной считается
только неизменная фиксация по запросу IMK или контроллера: она записывает последний проверенный в
разметке текст (см. раздел [«Адаптер для macOS»](macos.ru.md)).

**Отравленный дескриптор (poisoned handle).** Дескриптор движка или словарей, при работе с которым
была перехвачена паника Rust. Каждый последующий вызов с этим дескриптором возвращает `KR_POISONED`;
единственное допустимое действие — освободить его. См.
[границу C](learn/boundary.ru.md#%D1%88%D0%B0%D0%B3-3-%D0%BE%D1%81%D1%82%D0%B0%D0%BD%D0%BE%D0%B2%D0%B8%D1%82%D1%8C-%D0%BF%D0%B0%D0%BD%D0%B8%D0%BA%D1%83-%D0%BD%D0%B0-%D0%B3%D1%80%D0%B0%D0%BD%D0%B8%D1%86%D0%B5).

**План (plan).** Ответ Rust на одну клавишу: идентификатор, одно разрешённое действие (пропуск,
разметка, завершение или «недоступно»), текст, который должна содержать разметка до записи, текст
для записи и решение о клавише после записи. План является предложением и права на правку не даёт.

**Поколение (generation).** Счётчик, который увеличивается при каждом событии, делающем
недействительными сведения адаптера. Операция запоминает поколение, при котором она началась, и
сверяет его после каждого нативного вызова; расхождение означает, что в промежутке выполнился
обратный вызов, и операция прекращается. См.
[реентерабельность и тесты](learn/reentrancy-and-tests.ru.md#%D0%BF%D0%BE%D0%BA%D0%BE%D0%BB%D0%B5%D0%BD%D0%B8%D0%B5-%D0%B8-%D1%84%D0%BB%D0%B0%D0%B3-%D0%B7%D0%B0%D0%BD%D1%8F%D1%82%D0%BE%D1%81%D1%82%D0%B8).

**Подтверждение (acknowledgement).** Сообщение адаптера об исходе плана, передаваемое через
`kr_commit`: проверено, отказ до записи или исход неизвестен. Продвигает сеанс Rust только
проверенное подтверждение. См.
[Rust в ядре](learn/rust.ru.md#%D0%B7%D0%B0%D0%B1%D1%80%D0%B0%D1%82%D1%8C-%D0%B7%D0%BD%D0%B0%D1%87%D0%B5%D0%BD%D0%B8%D0%B5-%D1%80%D0%BE%D0%B2%D0%BD%D0%BE-%D0%BE%D0%B4%D0%B8%D0%BD-%D1%80%D0%B0%D0%B7).

**Разметка, собственная композиция (mark, owned composition).** Размеченный текст (англ. marked
text), то есть подчёркнутая композиция метода ввода, которую Keyrill сам поместил вызовом
`setMarkedText` и которая всё ещё ему принадлежит. Это единственный текст, который Keyrill вправе
изменять в режиме композиции; единственное исключение составляет режим совместимости. См.
[как работает Keyrill](how-it-works.ru.md#%D0%BF%D0%BE%D1%87%D0%B5%D0%BC%D1%83-%D0%BC%D0%B5%D1%82%D0%BE%D0%B4-%D0%B2%D0%B2%D0%BE%D0%B4%D0%B0).

**Разметка на границе (boundary mark).** Слово вместе с пробелом, которое остаётся размеченным после
пробела, чтобы исправление можно было отменить заменой собственной разметки Keyrill. Завершается
следующей клавишей. В ARCHITECTURE.md это состояние называется BoundaryRetained.

**Режим ввода (input mode).** Keyrill English или Keyrill Russian — два источника ввода, которые
устанавливает Keyrill; режим определяет, в какой раскладке печатают клавиши.

**Режим совместимости (compatibility backend).** Режим macOS для приложений, не поддерживающих
собственную композицию, например терминалов. Он посылает синтетические события клавиш и считает их
отправленными, но никогда не считает их проверенными правками. Это единственное исключение из
правила, по которому правится только собственная композиция; см.
[ADR 006](adr/006-compatibility-backend.ru.md).

**Снимок (snapshot).** Неизменяемая, полностью разобранная копия словаря, которая публикуется
целиком в виде `Arc` и на месте никогда не изменяется. При неудачном разборе в силе остаётся
последний удачный снимок.

**Страж (guard).** Перехватчик событий режима совместимости, работающий только на наблюдение. Он
следит за мышью, клавишами навигации, сочетаниями клавиш и сменой источника, не читая символов;
каждое такое событие прекращает отслеживание и увеличивает общее для процесса поколение стража,
которое проверяется перед каждой отправкой событий. См. раздел
[«Адаптер для macOS»](macos.ru.md#%D1%81%D0%BE%D0%B2%D0%BC%D0%B5%D1%81%D1%82%D0%B8%D0%BC%D0%BE%D1%81%D1%82%D1%8C).

**Тестовая политика (fixture policy).** Политика для тестов, которая преобразует только `ghbdtn` и
`руддщ`, чтобы тесты сеанса не зависели от модели.

**Уровень (tier).** Способ, которым Keyrill обслуживает приложение; выбирается по идентификатору
пакета: композиция, совместимость (автоматическая и ручная или только ручная) или «выключено». См.
[адаптер для macOS](macos.ru.md#%D1%83%D1%80%D0%BE%D0%B2%D0%BD%D0%B8-%D0%BF%D1%80%D0%B8%D0%BB%D0%BE%D0%B6%D0%B5%D0%BD%D0%B8%D0%B9).

**Условная клавиша (provisional key).** Клавиша вроде `[` или `;`, которая в английской раскладке
печатает знак препинания, а в русской — букву. В английском режиме такая клавиша может начинать или
продолжать слово, поскольку слово может оказаться русским, набранным в неверной раскладке.

**Явное намерение (explicit intent).** Ручное преобразование или отмена, выполненные пользователем.
Явное намерение прекращает автоматический вывод до конца данного слова, так что вывод никогда не
отменяет выбор пользователя.

**Secure Input.** Режим macOS, в котором ввод с клавиатуры идёт только в приложение с фокусом;
используется для полей паролей
([TN2150](https://developer.apple.com/library/archive/technotes/tn2150/_index.html)). Пока этот
режим включён, Keyrill пропускает все клавиши и ни к чему не обращается.

**TIS.** Text Input Sources, интерфейс Carbon в `HIToolbox/TextInputSources.h` (функции с префиксом
`TIS...`), который перечисляет, включает и выбирает источники ввода. Apple описывает этот интерфейс
только в указанном заголовочном файле. Keyrill пользуется им, чтобы перечислять источники ввода,
читать их свойства и следить за сменой источника, и не пользуется там, где внутри процесса самого
метода ввода его ответы ненадёжны
([переключение источников ввода](macos.ru.md#%D0%BF%D0%B5%D1%80%D0%B5%D0%BA%D0%BB%D1%8E%D1%87%D0%B5%D0%BD%D0%B8%D0%B5-%D0%B8%D1%81%D1%82%D0%BE%D1%87%D0%BD%D0%B8%D0%BA%D0%BE%D0%B2-%D0%B2%D0%B2%D0%BE%D0%B4%D0%B0)).
