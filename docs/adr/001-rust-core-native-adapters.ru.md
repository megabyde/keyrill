# ADR 001: ядро на Rust и нативные адаптеры

> [!TIP]
> **Статус:** принято.

Преобразование раскладки, разбиение на слова, словари, оценка, политика, а также состояние слова и
отмены сосредоточены в одном крейте на Rust 2024; в этом крейте запрещён `unsafe`, и он не зависит
от операционной системы. Для каждой платформы пишется собственный нативный адаптер: для
InputMethodKit в macOS — на Objective-C++ с ARC, для Windows и Linux — на том языке, которого
требует платформенная среда ввода. Ядро и адаптер взаимодействуют через узкий версионированный
интерфейс C ABI с непрозрачными дескрипторами, тегами фиксированной ширины, явно передаваемыми
длинами и копируемыми буферами; сырые указатели и перехват паники остаются в крейте `keyrill-ffi`.

Были рассмотрены следующие альтернативы: ядро на C++; логика, повторённая для каждой платформы
заново; адаптер IMK на чистом Rust с использованием `objc2`. Последний вариант добавляет работу по
согласованию языков и времени жизни объектов, не давая никакого выигрыша по сравнению с нативным
Objective-C++.

Общей для всех платформ абстракции правки документа нет. IMK, TSF и среды ввода Linux различаются
блокировками, обратными вызовами, работой с фокусом, выбором источника ввода и способом опознания
композиции; общий фасад скрыл бы эти различия, вместо того чтобы проверить каждое из них. Нативный
код остаётся небезопасным в широком смысле слова, хотя ядро таковым не является.

Пересматривать границу между ядром и адаптерами следует только при наличии конкретных доказательств
того, что она не справляется со своей задачей, а вводить общую абстракцию правки — только после
того, как два работающих адаптера выявят один и тот же контракт.
