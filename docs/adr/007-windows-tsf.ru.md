# ADR 007: Windows Text Services Framework

Решение принято для проверенных сценариев нативного тестового редактора и Блокнота.
Приёмка итоговой сборки в приложениях ещё предстоит.

В Windows право редактировать документ принадлежит нативной текстовой службе TSF. Она реализует
[архитектуру](../../ARCHITECTURE.ru.md) с помощью разрешённых сеансов редактирования, явных
контекстов и собственных композиций. Адаптер, регистратор, настройки, установщик и тестовые
инструменты написаны на Rust с windows-rs. Поведение общего ядра и C ABI остаётся переносимым.
UI Automation служит независимым источником наблюдений для тестов и диагностики.

Согласно документации Microsoft, результат запроса и результат самого сеанса редактирования
возвращаются раздельно, а владелец может отклонить создание композиции, вернув при этом успех и
нулевой указатель на композицию. Эталонный пример Microsoft не обрабатывает правильно ни то, ни
другое. Блокировки не обеспечивают ни отката, ни сохранения фокуса, а сбой библиотеки, загруженной в
процесс редактора, может привести к аварийному завершению этого редактора.

[Результаты проверки Windows](../windows.md) включают наблюдения за документом и курсором в
нативном редакторе и Блокноте, контролируемые отказы в сеансе и отдельные опыты с физической
клавиатурой. Они подтверждают применимость TSF в проверенных условиях.
[План завершения работ](../windows-completion-plan.md) требует повторно проверить приложения,
ввод с физической клавиатуры и установку на одной итоговой сборке.

Для расширения круга поддерживаемых полей нужен [контракт нативного элемента
управления](../windows-admission-contract.md). В неподдерживаемых полях служба пропускает ввод.
Для приёмки Terminal ещё предстоит отличить обычный ввод от секретного, проверить чтение собственной
композиции и порядок байтов, полученных дочерним процессом. Реализация через перехват клавиш и
SendInput требует отдельного архитектурного решения.
