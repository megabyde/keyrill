# Keyrill

[English version](README.md)

Keyrill исправляет ошибки раскладки при наборе английского и русского текста: `ghbdtn` превращается
в `привет`, а `руддщ` — в `hello`. Это локальный метод ввода, состоящий из движка на Rust,
версионированного интерфейса C ABI (двоичного интерфейса, через который к движку обращается нативный
код) и нативного адаптера к InputMethodKit для macOS. Вывод (англ. inference), то есть решение о
том, набрано ли слово в неверной раскладке, выполняется без обращения к сети, на основе замороженной
частотной модели и собственных словарей пользователя: файлов Vim `.add`, если пользователь их ведёт,
и слов, которым он обучил macOS командой Learn Spelling. Набранный текст не записывается в журнал,
не сохраняется и не передаётся по сети.

> [!NOTE]
> Это альфа-версия. Адаптер существует только для macOS. Движок и ABI от платформы не зависят, а
> адаптеры для Windows и Linux остаются открытой задачей (см. раздел о
> [переносе на другие платформы](docs/porting.ru.md)).

## Принцип работы

Пользователь выбирает источником ввода **Keyrill EN** или **Keyrill RU** вместо стандартных
раскладок «США» и «Русская». При нажатии пробела Keyrill решает, не предназначалось ли только что
набранное слово для другой раскладки, и, если доводы достаточно сильны, заменяет его. Неизвестные и
технические слова, слова со смешанной письменностью или смешанным регистром, а также слова,
защищённые личным словарём, остаются в набранном виде: движок предпочитает пропустить исправление,
чем исправить неверно.

| Действие | Клавиши |
| -- | -- |
| Преобразовать текущее слово независимо от модели | Control+Option+K |
| Отменить исправление сразу после него, до следующей клавиши | Control+Option+Z |
| Вернуть исходное слово и оставить его | Escape, пока слово ещё размечено |

Первая строка меню ввода сообщает, готово ли автоматическое исправление в текущем приложении, а если
нет, то почему. Строки под ней появляются, только когда что-то требует внимания.

После автоматического исправления Keyrill переключается на режим ввода, соответствующий языку
исправленного слова, так что следующее слово набирается в нужной раскладке; отмена исправления
переключает режим обратно. Тот, кто предпочитает переключаться сам, может выключить эту функцию в
настройках.

Keyrill правит текст одним из трёх способов; способ выбирается для каждого приложения в момент,
когда оно получает фокус:

- **Композиция** (TextEdit, Safari, Firefox). Пока слово набирается, оно остаётся размеченным
  (подчёркнутым), и Keyrill заменяет только эту разметку, предварительно проверив её точный текст,
  диапазон и положение курсора. Если проверка не проходит до записи, Keyrill ничего не записывает и
  оставляет это слово в покое. Если ответ приложения после записи не совпадает с ожидаемым,
  результат записи неизвестен: Keyrill фиксирует размеченный текст в точности в том виде, в каком
  приложение его возвращает, при условии что этот текст по-прежнему занимает диапазон разметки, и
  прекращает исправление; ничего не угадывается и не повторяется. Со следующего слова исправление
  возобновляется, только если за эту активацию уже была проверена хотя бы одна запись; в противном
  случае, а также после второго неизвестного исхода оно остаётся выключенным в данном поле до тех
  пор, пока пользователь не переключится в другое место и обратно.
- **Совместимость** (терминалы, редакторы кода, Microsoft Office и все приложения, не входящие в
  списки). Сочетания Control+Option+K и Control+Option+Z переписывают слово, посылая нажатия
  Backspace и замену. Автоматическое исправление в этом режиме выключено, если только пользователь
  не включит его в настройках для приложений вне списков. Keyrill не видит, что приложение в
  действительности удалило или вставило, поэтому набор во время переписывания, смена фокуса,
  автодополнение и текстовые интерфейсы (TUI) могут привести к потере нажатий или порче слова. Этому
  режиму необходимы разрешения Accessibility и Input Monitoring. Принятый компромисс описан в
  [ADR 006](docs/adr/006-compatibility-backend.ru.md).
- **Выключено** (менеджеры паролей, удалённые рабочие столы, виртуальные машины). Клавиши проходят
  без изменений.

Подменю **Correction in This App** в меню ввода показывает режим текущего приложения и позволяет его
изменить. Встроенные списки приведены в описании
[адаптера для macOS](docs/macos.ru.md#%D1%83%D1%80%D0%BE%D0%B2%D0%BD%D0%B8-%D0%BF%D1%80%D0%B8%D0%BB%D0%BE%D0%B6%D0%B5%D0%BD%D0%B8%D0%B9).

## Установка из исходного кода

Для установки необходим компьютер на Apple Silicon с macOS, Command Line Tools и Rust (при первом
запуске rustup устанавливает точную версию инструментов, указанную в `rust-toolchain.toml`).

1. Соберите, подпишите и скопируйте альфа-версию в папку методов ввода:

   ```console
   $ make install
   ```

   Пакет подписывается ad hoc, поэтому у каждой сборки своё требование к подписи кода, и после
   каждого обновления macOS может заново запрашивать разрешения для режима совместимости. Чтобы
   требование не менялось, создайте в программе «Связка ключей» самоподписанный сертификат для
   подписи кода и передайте его имя: `make install SIGN_IDENTITY="Keyrill Local"`. Команда
   `make bundle` собирает и подписывает `target/alpha.noindex/KeyrillAlpha.app`, не устанавливая
   его.

1. В разделе «Системные настройки > Клавиатура > Источники ввода» (System Settings > Keyboard >
   Input Sources) добавьте **Keyrill EN** и **Keyrill RU** и выберите один из них. Только что
   установленный метод ввода иногда появляется в списке лишь после выхода из системы и повторного
   входа.

1. Откройте пункт **Settings…** в меню ввода Keyrill, включите автоматическое исправление и
   проверьте пути к файлам английского и русского словарей. По умолчанию это
   `~/.vim/spell/en.utf-8.add` и `~/.vim/spell/ru.utf-8.add`; отсутствующий файл по пути по
   умолчанию считается пустым, так что пользователю, не работающему с Vim, эти пути можно не менять.
   Если же отсутствует файл по пути, выбранному пользователем, автоматическое исправление остаётся
   выключенным: так опечатка в пути не лишит защищённых слов незаметно. Слова, добавленные командой
   Learn Spelling в любом приложении, также защищены.

1. Для режима совместимости разрешите программе Keyrill Alpha доступ в разделах «Конфиденциальность
   и безопасность > Универсальный доступ» и «Мониторинг ввода» (Privacy & Security > Accessibility и
   Input Monitoring). Когда активно приложение в режиме совместимости, Keyrill проверяет оба
   разрешения, не запрашивая их, а меню ввода показывает, каких не хватает. Без этих разрешений
   такие приложения получают обычный набор без исправления.

Для обновления выберите стандартную раскладку «США» и снова выполните `make install` с тем же
значением `SIGN_IDENTITY`. Команда завершает работающий сервер перед заменой пакета, поскольку
копирование поверх пакета работающего сервера может привести к его остановке из-за недействительной
подписи кода.

Новый сервер запускается при повторном выборе режима Keyrill. Настройки сохраняются.

Для удаления Keyrill уберите оба режима из источников ввода, завершите сервер, удалите
`~/Library/Input Methods/KeyrillAlpha.app` и, если нужно удалить также настройки, выполните
`defaults delete org.keyrill.inputmethod.alpha`. Файлы словарей пользователя Keyrill никогда не
изменяет.

## Известные ограничения

- Режим Secure Input прекращает исправление, однако Keyrill распознаёт не каждое поле пароля и не
  каждый скрытый запрос в терминале. При выключенном Secure Input режим совместимости может хранить
  в памяти конфиденциальный ввод.
- Исправить можно только набираемое слово: в режиме композиции это разметка, в режиме совместимости
  это отслеживаемое слово. Произвольный уже зафиксированный фрагмент и выделения не преобразуются.
- В английском режиме клавиши `[ ] ; ' , .` и `\` считаются буквами, поскольку в русской раскладке
  на них находятся буквы х, ъ, ж, э, б, ю и ё: `[jhjij` превращается в `хорошо`. Пока слово
  размечено, «умные» кавычки редактора и автоматическая вставка парных скобок к этим клавишам могут
  не применяться.
- Автоматическое исправление запускается только пробелом, поэтому слово, за которым сразу следует
  знак препинания или Return, остаётся в набранном виде; сочетание Control+Option+K тем не менее его
  преобразует.
- В терминалах, которые читают клавиши напрямую, сочетания Control+Option+K и Control+Option+Z могут
  дойти и до самого терминала.
- При наборе целых предложений тестовой выборки в неверной раскладке автоматическое исправление
  исправляет около 46 % русских и 60 % английских токенов и не делает ложных исправлений в тех же
  предложениях, набранных правильно (см. раздел
  [«Движок»](docs/engine.ru.md#%D0%BE%D1%86%D0%B5%D0%BD%D0%BA%D0%B0)).
