# Keyrill

[English version](README.md)

Keyrill исправляет ошибки раскладки при наборе английского и русского текста: `ghbdtn` превращается
в `привет`, а `руддщ` в `hello`. Keyrill работает без сети. Альфа-версия доступна для macOS и
Windows. Поддержка Linux запланирована.

[Установка в macOS](#macos) · [Установка в Windows](#windows)

## Принцип работы

Выберите источник ввода Keyrill для английского или русского языка. Если включено автоматическое
исправление, по пробелу Keyrill проверяет только что набранное слово и преобразует его, когда данные
указывают на другую раскладку. Keyrill использует встроенную частотную модель и защищает слова из
личных словарей. Набранный текст не записывается в журнал, не сохраняется и не передаётся по сети.

| Действие | macOS | Windows |
| -- | -- | -- |
| Преобразовать текущее слово вручную | Control+Option+K | Левый Ctrl+левый Alt+K |
| Сразу отменить исправление | Control+Option+Z | Левый Ctrl+левый Alt+Z |
| Вернуть исходное слово и завершить композицию | Escape | Escape |

Сочетания действуют на текущее слово в поддерживаемых полях. В Windows используйте физические
клавиши K и Z и при наборе в русской раскладке.

### Работа в macOS

Выберите **Keyrill EN** или **Keyrill RU**. Меню ввода показывает, доступно ли исправление. Подменю
**Correction in This App** меняет режим текущего приложения. Переключение источника после
автоматического исправления можно отключить в настройках.

- **Композиция** (TextEdit, Safari, Firefox) меняет только размеченное слово после проверки текста,
  диапазона и курсора. См.
  [правила редактирования в режиме композиции](docs/macos.ru.md#%D0%BA%D0%BE%D0%BC%D0%BF%D0%BE%D0%B7%D0%B8%D1%86%D0%B8%D1%8F).
- **Совместимость** (терминалы, редакторы, Microsoft Office и другие приложения вне списков)
  имитирует Backspace и набор. Для приложений вне списков по умолчанию доступно ручное исправление,
  автоматическое включается в настройках. Этот режим требует разрешений Accessibility и Input
  Monitoring. Набор во время замены, смена фокуса, автодополнение и текстовые интерфейсы могут
  привести к потере нажатий или порче слова. См.
  [ADR 006](docs/adr/006-compatibility-backend.ru.md).
- **Выключено** пропускает клавиши без изменений в исключённых приложениях, например менеджерах
  паролей и клиентах удалённого рабочего стола.

Встроенные списки приведены в разделе
[«Уровни приложений»](docs/macos.ru.md#%D1%83%D1%80%D0%BE%D0%B2%D0%BD%D0%B8-%D0%BF%D1%80%D0%B8%D0%BB%D0%BE%D0%B6%D0%B5%D0%BD%D0%B8%D0%B9).

### Работа в Windows

Выберите **Keyrill English** или **Keyrill Русский**. Автоматическое исправление по умолчанию
выключено. Чтобы включить его, выберите **Enable automatic correction in admitted controls** в
Keyrill Settings.

Исправление проверено в основном поле редактора Блокнота 11.2609.11.0 x64. В неподдерживаемых полях
ввод проходит без изменений. Версии, поля и результаты приведены в
[проверках приложений Windows](docs/windows.md#application-qualification).

## Установка из исходного кода

### macOS

Для установки необходим компьютер на Apple Silicon с macOS, Command Line Tools и Rust (при первом
запуске rustup устанавливает точную версию инструментов, указанную в `rust-toolchain.toml`).

1. Соберите, подпишите и скопируйте альфа-версию в папку методов ввода:

   ```console
   $ make install
   ```

   Пакет подписывается ad hoc, поэтому у каждой сборки своё требование к подписи кода, и после
   каждого обновления macOS может заново запрашивать разрешения для режима совместимости. Чтобы
   требование не менялось, создайте в программе «Связка ключей» самоподписанный сертификат для
   подписи кода и передайте его имя: `make install SIGN_IDENTITY="Keyrill Local"`. Команда
   `make bundle` собирает и подписывает `target/alpha.noindex/KeyrillAlpha.app`, не устанавливая
   его.

1. В разделе «Системные настройки > Клавиатура > Источники ввода» (System Settings > Keyboard >
   Input Sources) добавьте **Keyrill EN** и **Keyrill RU** и выберите один из них. Только что
   установленный метод ввода иногда появляется в списке лишь после выхода из системы и повторного
   входа.

1. Откройте пункт **Settings…** в меню ввода Keyrill, включите автоматическое исправление и
   проверьте пути к файлам английского и русского словарей. По умолчанию это
   `~/.vim/spell/en.utf-8.add` и `~/.vim/spell/ru.utf-8.add`; отсутствующий файл по пути по
   умолчанию считается пустым, так что пользователю, не работающему с Vim, эти пути можно не менять.
   Если же отсутствует файл по пути, выбранному пользователем, автоматическое исправление остаётся
   выключенным: так опечатка в пути не лишит защищённых слов незаметно. Пункт **Use words added with
   Learn Spelling** по умолчанию выключен. Чтобы защищать и эти слова, нажмите **Choose…** рядом с
   флажком, выберите файл Apple `LocalDictionary` в каталоге, который откроет диалог, затем нажмите
   **Save**. macOS может выдать разрешение при выборе файла; кнопка Cancel в настройках не отзывает
   уже выданный доступ. Ошибки чтения видны в меню ввода. Если после перезапуска или обновления
   доступ утрачен, выберите файл ещё раз. Без разрешения исправление продолжает работать без
   выученных слов.

1. Для режима совместимости разрешите программе Keyrill Alpha доступ в разделах «Конфиденциальность
   и безопасность > Универсальный доступ» и «Мониторинг ввода» (Privacy & Security > Accessibility и
   Input Monitoring). Когда активно приложение в режиме совместимости, Keyrill проверяет оба
   разрешения, не запрашивая их, а меню ввода показывает, каких не хватает. Без этих разрешений
   такие приложения получают обычный набор без исправления.

Для обновления выберите стандартную раскладку «США» и снова выполните `make install` с тем же
значением `SIGN_IDENTITY`. Команда завершает работающий сервер перед заменой пакета, поскольку
копирование поверх пакета работающего сервера может привести к его остановке из-за недействительной
подписи кода.

Новый сервер запускается при повторном выборе режима Keyrill. Настройки сохраняются.

Для удаления Keyrill уберите оба режима из источников ввода, завершите сервер, удалите
`~/Library/Input Methods/KeyrillAlpha.app` и, если нужно удалить также настройки, выполните
`defaults delete org.keyrill.inputmethod.alpha`. Файлы словарей пользователя Keyrill никогда не
изменяет.

### Windows

Для установки нужна Windows x64 и
[инструменты сборки](docs/windows.md#build-and-check-without-installation). В пакет входят адаптеры
TSF для 64- и 32-разрядных приложений.

1. [Соберите и проверьте пакет](docs/windows-package.md#candidate-preparation).
1. Добавьте стандартные раскладки «США» и «Русская», затем
   [установите пакет с правами администратора](docs/windows-package.md#explicit-maintainer-commands).
1. Включите и выберите один из профилей ввода Keyrill в Windows.

## Известные ограничения в macOS

- Режим Secure Input прекращает исправление, однако Keyrill распознаёт не каждое поле пароля и не
  каждый скрытый запрос в терминале. При выключенном Secure Input режим совместимости может хранить
  в памяти конфиденциальный ввод.
- Исправить можно только набираемое слово: в режиме композиции это разметка, в режиме совместимости
  это отслеживаемое слово. Произвольный уже зафиксированный фрагмент и выделения не преобразуются.
- В английском режиме клавиши `[ ] ; ' , .` и `\` считаются буквами, поскольку в русской раскладке
  на них находятся буквы х, ъ, ж, э, б, ю и ё: `[jhjij` превращается в `хорошо`. Пока слово
  размечено, «умные» кавычки редактора и автоматическая вставка парных скобок к этим клавишам могут
  не применяться.
- В терминалах, которые читают клавиши напрямую, сочетания для ручного исправления могут дойти до
  самого терминала.
